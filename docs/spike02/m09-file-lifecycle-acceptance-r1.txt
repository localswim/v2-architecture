Acceptance details
Byte fixtures include empty, binary with NUL/high-bit bytes and a non-ASCII name.
Generate 10 MiB and 10 MiB+1 inputs deterministically in private test storage.
Generate distinct digest content to make the protected union exactly64 MiB.
One further new byte refuses; duplicate protected content remains admissible
subject to normal authority/CAS. Detached protected bytes still count.

Read tests compare exact selected board/incarnation/card/attachment identity,
both revisions, all metadata fields, source identity and attribution basis.
Retained view contains only surviving non-current metadata. Existing history
tests compare exact available snapshots/tombstones and coverage gaps. Historical
metadata availability never grants ordinary-byte download eligibility.

NO_CHANGE is durable NOT_COMMITTED. It changes no card/board/event/pin counter.
Compare the whole permitted original receipt as well as domain state. A second
fresh opId and current revisions is required to test repeated detach NO_CHANGE.
Reusing the original opId tests immutable receipt resolution instead.

Transfer integrity assertions include complete size/SHA256 and exact bytes.
Browser assertions say Offered only after verification. Native success requires
destination readback with exact bytes and no-overwrite/path defenses. Missing or
corrupt required blobs fail before successful response/publication and fence
the store according to existing integrity behavior. Publication uncertainty
does not claim absence or blindly repeat the save.

Fault points include preparation write/readback, before writer, before COMMIT,
after COMMIT/before response, cleanup/reconciliation, partial/truncated upload,
lost download and native final-publication readback. Assert no partial mutation,
or exact original resolution/UNKNOWN when delivery is uncertain. Never call a
failure noncommitted solely because the client lost a response.

Conservation comparison is exhaustive
- Cards, policies and policy history/pins, actors, approvals, priority,
  relationships, hierarchy, archive flags and workflow/Attention semantics.
- Every current and historical reference, snapshot state, coverage/floor,
  tombstone and activity, including source incarnation and actor attribution.
- Full and compact original records, immutable canonical intent/result bytes,
  source archives, byte facts, retention metadata and lineage.
- Every protected blob with exact bytes, length and digest, reconstructed
  current/history/operation pins and deduplicated quota union.

Restore comparison applies only the existing explicit current-incarnation,
current-reference rebasing, source-ledger placement and lineage transformations.
Record them field by field. Preserve the complete comparison output for source
to first runnable restore and first restore to second runnable restore. Current
read parity alone is insufficient. Detach must not synthesize an entity
tombstone. Later authorized pruning must produce its existing genuine tombstone.

No tests here authorize new cover UI, automatic GC, extra collectors or product
telemetry. If a stored cover representation is discovered, enforce the contract
extension gate before enabling detach on it. Use the shared Valkey/Webdis queue
for bounded sanitized browser diagnostics. Export required evidence before
deleting each owned mailbox. Never log card text, bytes, credentials or raw URLs.

Response-byte amendment A1, 2026-11-05
M09.02 review found proposed client caps of16KiB inspect,256KiB browser list
and512KiB CLI list reject valid legacy labels/pages. Actor.Label has no such
stored bound. This amendment sets one128MiB hard file-read response cap and
one1MiB normal list target, measured as the full encoded UTF-8 response.
An oversized first item may occupy a singleton page up to the hard cap.
Server uses SetEscapeHTML(false); all surfaces preserve exact decoded labels.
Physical10/base5 and archive/member limits remain unchanged.
