M01 INDEPENDENT WORK BREAKDOWN R1
2026-10-27 | Proposal for owner review; not a replacement execution baseline

Purpose and provenance
Build a usable localhost workspace over independent SQLite boards: three boards
in two projects, ordinary browser and CLI access, truthful Attention, shared pins,
and correctly isolated private work. Preserve the accepted one-board product.
This breakdown starts from that outcome and code at implementation628eb72.
The author has already seen the earlier decomposition; this is fresh analysis,
not a blind or independently isolated clean-room exercise. Comparison is recorded
separately. No product code or accepted task/dependency changes are made here.

Working boundaries
- Go owns authority and writes; TS owns browser interaction. Loopback HTTP only.
- Reuse board transactions, domain rules, outcome ledger and private recovery.
- Assigned priority, human-only approval, one writer per board and UNKNOWN/no
  automatic replay remain. Navigation never grants rights or submits a mutation.
- Four qualified lanes remain. Blocked/Needs Terry are not configured until M02.
- Synthetic data only. No real import, cutover, TLS, accounts, new framework,
  workflow engine, monitor, publishing or new attachment feature set.
- These are proposed work packages, not promises that each fits one agent turn.
  A package that cannot fit a bounded author/review cycle must be split before
  execution, preserving its acceptance and dependencies rather than silently growing.

Independent breakdown

A. Fix the integration decisions and acceptance fixture
Deliver: a short workspace contract plus three-board/two-project fixture and
retained/remaining/intentional-difference matrix. Decide stable route keys versus
durable board identity, configured membership and explicit creation, host topology,
board session/bootstrap and CLI selection, lifecycle, catalog freshness/ordering,
and preference/window ownership. Choose the smallest supported composition;
do not redesign accepted storage or select a framework. Name adapter/file owners,
generated-contract changes and acceptance cases before parallel work.
Exit: independently reviewed proposal and owner acceptance. No production code.
Requires: accepted M01 planning packet; available now.

B. Make the runtime and transport safely address independent boards
Deliver: the necessary host/board runtime bridge, board-selected bootstrap/session
and request dispatch, while retaining single-board startup. This may reuse engines
or adapt existing runtimes as A decides; a one-listener extraction is not assumed.
Exercise two actual synthetic boards using resolved registrations supplied by a
test harness; persisted workspace configuration belongs to C. Both have separate
ownership, authority, revisions and outcome records. Browser cookies/session calls
must select the intended board; CLI bot credentials cannot gain human rights.
Exit: actual HTTP wrong-board/refusal, cross-board read/write, restart/credential
rotation and admitted-request drain checks; affected generated bindings agree.
Requires: A accepted. Independent authority/concurrency review before handoff.

C. Persist workspace membership and complete board lifecycle
Deliver: configured projects, stable board keys/labels and the chosen bounded
registration/discovery/create behavior. Provide actual initialization and reopening
of three synthetic boards. Registry configuration and preferences stay separate
from board state; adding a board cannot silently replace an existing identity.
Exit: restart preserves membership and stores; duplicate aliases/identity conflicts
and unsafe paths refuse; missing/invalid/busy members do not disable healthy ones.
Recheck membership and target identity at use. Preserve existing --data operation.
Requires: A and B accepted. Physical path/ownership behavior gets native checks.

D. Deliver explicit workspace selection through the real CLI
Deliver: project/board list and exact target selection/initialization using C and
B; preserve the existing --data interface and board-local private evidence store.
Exit: built CLI creates/edits/comments against A while same-ticket B is unchanged,
then deliberately selects B. Missing, ambiguous, unavailable and replaced targets
refuse without default-board fallback, direct SQL mutation or automatic replay.
Existing original-operation lookup remains bound to its source context.
Requires: B and C accepted. Independent review; CLI remains automation-only.

E. Make browser board context and private-work switching safe
Deliver: a board-scoped client/session and view-lifetime controller using existing
draft/original stores. Keep active editor, focus and draft selection window-local;
records retain full installation/board/incarnation/actor context and operation IDs.
Explicitly handle detaching/reattaching a view rather than assuming destroy/remount
preserves its current editor. Do not rewrite recovery storage or retention.
Exit: delayed A reads/mutations cannot repaint or resolve B; switching back restores
the right editor/base. Pending originals stay with A. Two windows, including the
same board in both, retain independent input/selection. Reconnect never resubmits.
If private persistence fails, retain input and prevent destructive app navigation
or require explicit discard; never promise durable recovery through a forced reload
with unavailable storage. Prove the controller against real board sessions plus
deterministic late-response/storage-denial cases before using it for navigation.
Requires: B and C accepted. Independent recovery/authority review; no pin dependency.

F. Project truthful Attention and bounded refresh results
Deliver: Go catalog projection and its read contract: supported category counts,
availability/freshness, committed activity ordering and stable ties. Known zero,
not configured, stale and unavailable are different. Archived items do not inflate
counts; catalog reads do not mutate priorities, approvals or boards.
Exit: actual board mutations appear on subsequent real catalog reads; a bounded
failed/timed-out/slow member does not stall healthy entries
or overwrite good data with a fabricated zero. Retry/restart recovers truthfully.
Define bounded polling or another minimal refresh mechanism in A; no new event bus.
Requires: C accepted. No browser-shell dependency; integrated display belongs to G.

G. Deliver the ordinary workspace chooser and browser navigation
Deliver: the thin project/board shell consuming C, E and F, Attention with automatic
refresh, /board/<project>/<board> deep links, Back/Forward, keyboard selection,
per-window active route/view state, clear loading/error/retry and board composition.
No full page reload on switch.
Exit: normal browser selects all three boards and edits the intended one. Unknown
routes remain unavailable; they never select a fallback board. Cold deep links,
refresh, two windows and rapid navigation preserve E's isolation and input rules.
Browser/CLI writes update the correct count without manual page reload. Failed
refresh preserves labeled stale data and lets healthy boards remain usable.
Requires: C, E and F accepted. This handoff must already be safe to switch boards.

H. Add shared pins without sharing active-window context
Deliver: workspace-persisted pins/manual ordering and keyboard controls. Separate
preference revision/conflicts from board revisions and route state.
Exit: a second window observes reordered pins; browser/host restart preserves them.
Simultaneous stale writes and failed saves are visible; shared updates cannot steal
another window's route, editor, focus or scroll. Malformed saved configuration is
reported, not silently reset. Pins grant no membership or approval rights.
Requires: C and G accepted; never a prerequisite of E.

J. Independently demonstrate and hand off M01

Sequencing and useful parallelism
A -> B -> C -> {D, E, F}; {E, F} -> G -> H;
{D, E, F, G, H} -> I -> J.
These arrows retain owner-acceptance gates. Planned parallelism is possible only
after interfaces/file owners are fixed and within four direct agents/depth one.
Use rolling authors then fresh reviewers; do not reserve idle reviewer slots.

Why these boundaries
The current runtime combines store/authority/listener/descriptor lifetime:
internal/transport/local/runtime.go:154,174,202,297,311,317. Bootstrap/session URLs
are singleton routes (http.go:226,230); browser bootstrap reconnect refuses a
different board (web/src/api/local-session.ts:10,26,46). These are useful single-
board guarantees, not bugs. B makes their workspace extension an explicit unit.
The current BoardClient already addresses reads/mutations by board UUID and uses
full recovery context (client.ts:63,83,106). Reuse that work rather than replacing it.
BoardView.destroy clears the current editor (board/view.ts:59); the enclosing
SessionWorkspace destroys all child views (session-ui/workspace.ts:28). Recovery
records alone do not establish safe live navigation; E precedes G for that reason.
The CLI resolves private bot metadata and evidence from one selected data root
(cmd/localswim/local_entry.go:78,144,154). D must carry both selection and source-
bound original evidence through the workspace extension.
