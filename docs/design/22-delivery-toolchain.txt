Repository and dependency direction
Recommend one future product repository with one root Go module and independently
locked web/ and tools/contracts/ Node packages. Keep the architecture repository
as decision history. cmd/ contains thin host, CLI, monitor and publisher entry
points; internal/core/ owns domain/application policy and ports. Storage, HTTP,
OS lifecycle and worker adapters depend inward. Live CLI writes reach the host;
exclusive maintenance reuses the same core/storage adapter. Project launchers
delegate to this shared product; no project forks of board or monitor logic.
No framework is selected here; #0016's proposal and #0019 handoff meet #0024 later.

Build and development contract
Propose cross-platform command names generate, check, build, dev and package,
implemented later through one thin orchestration entry point. generate consumes
only repository-local schemas and pinned tools; check rejects regeneration drift,
invalid UTF-8/LF, dependency changes and contract mismatch. build requires explicit
TS7 checking before asset compilation, then stages only allowlisted production
assets beneath internal/assets/dist for go:embed [S6]. No credentials, board files,
development server, absolute paths or unreviewed remote assets enter the bundle.

dev uses synthetic data, the same authenticated Go origin and an explicit local
asset override; browser refresh is sufficient initially. A later development proxy
must preserve32's TLS, exact authority/origin and session binding; hot reload cannot
bypass them. Trust provisioning remains a qualified deployment step requiring
separate installation authorization, never an automatic developer/build action.

Reproducibility and local distribution flow
Pinned source -> verified dependency restore -> generate/drift check -> TS7 check
-> qualified assets -> Go platform build -> deterministic unsigned archive ->
checksums/SBOM/notices/provenance -> separately signed release manifest.
Record source/schema/assets/toolchain digests and target settings. Pin go.mod/go.sum
and both Node lockfiles; reject implicit toolchain downloads, remote schema refs
and unreviewed install scripts. Normalize archive order/timestamps/permissions,
use Go trimpath and fixed version metadata; compare two clean builds before claiming
byte reproducibility. Signing/notarization outputs are checked separately.

Offer portable per-platform archives first: explicit install location, platform
binary, embedded browser, licenses and trust/setup instructions; no Node/Go runtime
needed by users. Qualify CGO/native dependencies before claiming single-binary
portability. Signed installers are an alternative with platform maintenance cost.
Updates are explicit: verify provenance, drain host/workers under11, preserve board
and runtime roots, recover under10, then report readiness. Rollback requires format
compatibility; never overwrite private data or auto-downgrade it.

Decision and evidence
Recommend these boundaries; Terry reviews the generator isolation tradeoff and
later qualified platform matrix. Dependency inventory preserves upstream licenses
and notices; first-party MIT does not relicense dependencies. Enforce text UTF-8/LF
and final newline through .gitattributes/.editorconfig plus checks; preserve binaries.
No installs, builds, tests, repository initialization or compatibility success is
claimed. Source checks and scope review only; #0024 integrates #0019 before handoff.
